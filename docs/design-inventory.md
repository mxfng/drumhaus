# Component inventory

Status: living appendix to [design-language.md](./design-language.md).
Author: Max, July 2026.

This inventory drives the component-lift phase: it lists what is already shared, what in Drumhaus is design-language material worth extracting (with an honest coupling assessment), and what is app-specific by design.
Paths are relative to the repository root.

## C. App-specific by design

- Identity: `apps/drumhaus/src/shared/icon/drumhaus-logo.tsx`, `drumhaus-typography-logo.tsx`; the header designation text; `apps/drumhaus/src/shared/components/logo-sweep.tsx` (the logo as screen ornament).
- Chassis and layout: `apps/drumhaus/src/layout/drumhaus.tsx`, `controls-panel.tsx`, `header.tsx`, `footer.tsx`, `screen.tsx`; the design box in `apps/drumhaus/src/shared/store/layout-scale.ts`.
- Domain tokens: brand pin, track colors, variation colors, sequencer indicator colors, night background, play-button dimensions in `apps/drumhaus/src/app/styles/theme.css`; color tables in `apps/drumhaus/src/features/instrument/lib/colors.ts` and `apps/drumhaus/src/features/sequencer/lib/colors.ts`.
- Descriptor catalog: `apps/drumhaus/src/shared/param-control/descriptors/*` (parameter ranges, tapers, formats are instrument meaning, per the param-control README).
- Kit and preset semantics: `apps/drumhaus/src/features/kit/*`, `apps/drumhaus/src/features/preset/*` (selectors, dialogs, document model, history).
- Sequencer, groove, transport, master-bus, instrument compositions and stores: `apps/drumhaus/src/features/{sequencer,groove,transport,master-bus,instrument}/`.
- Night mode: `apps/drumhaus/src/features/night/*` (the star-field visualizer is Drumhaus's signature dark room).
- Session UI: `apps/drumhaus/src/features/session/components/link-control.tsx` (window-edge idiom is shared language, but this control was already earmarked for extraction with the bridge work, not the hardware package).

## D. Known deviations

Places where the code contradicts the language, found while writing it down.
Each is small; together they are the punch list that keeps the brand layer honest.

1. Canvas surfaces bypass the brand layer.
   `frequency-analyzer.tsx` and `waveform.tsx` hardcode `#ff7b00` (canvas `fillStyle` cannot take `var()` strings), and `pixelated-spinner.tsx` defaults to the same literal.
   A brand-overridden sibling reusing these would still draw orange; the lift should resolve the computed token once per draw instead.
2. `GainMeter` uses stock Tailwind palette colors (`bg-green-500`, `bg-yellow-500`, `bg-red-500`) and rgba shadow literals - the only stock-palette usage on the chassis.
   Legible as a traffic-light meter, but the colors are not tokens.
3. `SequencerStep` carries literal rgba values for its inset shadows (`rgba(176,147,116,...)`) and sheen (`rgba(255,255,255,...)`) instead of the shadow/highlight tokens they visually correspond to.
4. `packages/ui/src/toast.tsx` references `border-l-track-green`, a Drumhaus app token, from the shared package; in pulse that token is undefined.
   The success accent should be a shared token (or `--color-primary`).
5. Dialogs use Tailwind's stock `shadow-lg` rather than the neu ramp (`packages/ui/src/dialog.tsx`).
6. `--shadow-neu-xl` / `.neu-extra-tall` has no consumer anywhere.
   Either something should sit at that elevation or the step should be dropped from the ramp.
7. The active-state convention (`border-primary border-2 text-primary`) lives in an app helper and is duplicated by hand in pulse (inventory item B1).
8. `--font-family-pixel` in `packages/tokens/src/theme.css` duplicates `--font-pixel`.
9. `base.css` has a doubled selector typo: `[role="slider"]:focus-visible:focus-visible`.
10. Pulse hand-copies the base cursor/focus rules instead of sharing them (inventory item B16), and the `focus-ring` utility coexists with the global focus rules covering the same elements.
